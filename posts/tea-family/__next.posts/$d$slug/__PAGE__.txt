b:T53c0,<h1>TEA 家族：TEA、XTEA、XXTEA 原理与逆向识别</h1>
<blockquote>
<p>TEA 这一家子很适合放在一起看。最早的 TEA 追求的就是“小”，核心操作只有加法、异或和移位；XTEA 在它的基础上改了 key 的使用方式；XXTEA 又把两个 32 位 word 的处理扩展到一整串 word。逆向题喜欢它们也不奇怪，常量醒目，代码不长，稍微改几个参数就能变成一道新题。</p>
</blockquote>
<h2>图解：TEA 家族演进</h2>
<p>‍<img src="/uploads/20260514/renwu/tea-family-flow.svg" alt="TEA、XTEA、XXTEA 家族关系图"></p>
<p>这张图可以先当作“第一眼判断表”。TEA 和 XTEA 都是 64 bit block，差别主要在 key 下标怎么取；XXTEA 则不再是两个 word 对着转，而是把整个 <code>uint32_t</code> 数组作为一个大块来搅。</p>
<h2>实战识别</h2>
<p>TEA 家族最适合从常量下手。反编译窗口里搜 <code>0x9e3779b9</code>，有时也会搜到 <code>0x61c88647</code> 或 <code>0xC6EF3720</code>。只要搜到了，再去看附近有没有 <code>&#x3C;&#x3C; 4</code>、<code>>> 5</code>、<code>sum</code>、四个 32 位 key。看到这些东西，不用急着细分，先把它当 TEA 家族处理。</p>
<p>接下来才区分具体是哪一个。key 下标固定在 <code>k0/k1/k2/k3</code> 的，多半是 TEA；出现 <code>sum &#x26; 3</code>、<code>(sum >> 11) &#x26; 3</code> 的，多半是 XTEA；出现 <code>6 + 52 / n</code>、<code>MX</code> 那种一长串 <code>z/y/sum/p/e</code> 混合表达式的，就往 XXTEA 想。新手最容易卡在大小端和轮数上，尤其是 x86 程序直接把 <code>char *</code> 强转成 <code>uint32_t *</code> 时，基本就是小端，不要拿大端脚本硬跑。</p>
<p>逆向时不用给变量名太大压力。IDA 可能把 <code>v0/v1</code> 叫成 <code>v7/v8</code>，把 key 数组叫成 <code>a2</code>，这不影响理解。你只要把“两个 32 位数据 word、四个 32 位 key word、sum 怎么变化、循环几次”抄准，后面 Python 复现就能慢慢调出来。</p>
<p>新手做这类题不要一开始就想着“我要完全理解密码学证明”。更实际的目标是把二进制里的加密函数还原到脚本里。先让脚本对上一组输入输出，再去谈是不是 TEA、XTEA 或 XXTEA。</p>
<h2>1. 家族总览</h2>
<p>算法数据单位密钥常见轮数逆向识别点主要意义TEA64 bit，两个 <code>uint32_t</code>128 bit32 cycles<code>0x9e3779b9</code>、<code>&#x3C;&#x3C;4</code>、<code>>>5</code>、固定 <code>k0..k3</code>最初的 Tiny Encryption AlgorithmXTEA64 bit，两个 <code>uint32_t</code>128 bit32 rounds<code>sum &#x26; 3</code>、<code>(sum >> 11) &#x26; 3</code>改进 TEA 的 key 调度XXTEAn 个 <code>uint32_t</code>，n >= 2128 bit<code>6 + 52 // nMX</code>、<code>z/y/sum/e/p</code>、<code>6+52/n</code>宽分组，修正 Block TEA</p>
<p>这三个算法的底子是一样的：都吃 128 bit key，都在 32 位无符号整数上做加法、异或和移位，也都绕不开 <code>delta = 0x9e3779b9</code>。它们没有像 AES 那样在库里形成特别统一的“模式 + padding”封装，所以 CTF 里一定要贴着题目实现走。Python 复现时尤其要记得 <code>&#x26; 0xffffffff</code>，不然 C 里的自然溢出在 Python 里不会自动发生。</p>
<p>最重要的区别：</p>
<pre><code>TEA/XTEA: 每次处理 8 字节 block
XXTEA:    把整个 uint32_t 数组作为一个大 block
</code></pre>
<h2>2. 算法详解前的共同基础</h2>
<h3>2.1 32 位溢出</h3>
<p>C 里的 <code>uint32_t</code> 会自然溢出：</p>
<pre><code>uint32_t x = 0xffffffff;
x += 1;  /* x == 0 */
</code></pre>
<p>Python 整数不会溢出，所以 TEA 家族脚本必须写：</p>
<pre><code>x = (x + y) &#x26; 0xffffffff
</code></pre>
<p>忘记掩码是这类脚本里最容易犯的错。表面上代码还在跑，输出也有十六进制，但和题目里的 C 程序已经不是同一个算法了。</p>
<h3>2.2 delta</h3>
<pre><code>delta = 0x9e3779b9
</code></pre>
<p>标准 TEA/XTEA 32 轮解密时的 sum：</p>
<pre><code>0xC6EF3720 = 0x9e3779b9 * 32 mod 2^32
</code></pre>
<p>逆向里也常见：</p>
<pre><code>0x61c88647 = 2^32 - 0x9e3779b9
</code></pre>
<p>出现这个值也要想到 TEA 家族，因为有些代码用减法维护 <code>sum</code>。</p>
<h3>2.3 字节序</h3>
<p>算法处理的是 <code>uint32_t</code>，题目给的是 bytes。必须确认大小端：</p>
<pre><code>struct.unpack("&#x3C;2I", block)  # 小端
struct.unpack(">2I", block)  # 大端
</code></pre>
<p>逆向题如果看到 <code>uint32_t *p = (uint32_t *)buf</code>，在 x86/x64 上通常是小端。</p>
<h2>3. TEA</h2>
<h3>3.1 参数</h3>
<p>项目内容分组长度64 bit密钥长度128 bit状态<code>v0, v1</code>key<code>k0, k1, k2, k3</code>标准轮数32 cycles</p>
<h3>3.2 加密流程</h3>
<pre><code>sum = 0
repeat 32:
    sum += delta
    v0 += ((v1 &#x3C;&#x3C; 4) + k0) XOR (v1 + sum) XOR ((v1 >> 5) + k1)
    v1 += ((v0 &#x3C;&#x3C; 4) + k2) XOR (v0 + sum) XOR ((v0 >> 5) + k3)
</code></pre>
<p>TEA 的 key 使用方式很死板，更新 <code>v0</code> 用 <code>k0/k1</code>，更新 <code>v1</code> 用 <code>k2/k3</code>。这种固定感就是它和 XTEA 的一个分界。</p>
<h3>3.3 解密流程</h3>
<pre><code>sum = delta * 32
repeat 32:
    v1 -= ((v0 &#x3C;&#x3C; 4) + k2) XOR (v0 + sum) XOR ((v0 >> 5) + k3)
    v0 -= ((v1 &#x3C;&#x3C; 4) + k0) XOR (v1 + sum) XOR ((v1 >> 5) + k1)
    sum -= delta
</code></pre>
<p>解密顺序别写反。加密最后一步更新的是 <code>v1</code>，所以解密要先把 <code>v1</code> 减回去，再处理 <code>v0</code>。</p>
<h3>3.4 TEA 识别点</h3>
<pre><code>0x9e3779b9
循环 32 次
两个 uint32_t
四个 uint32_t key
&#x3C;&#x3C; 4
>> 5
固定 k0/k1/k2/k3
</code></pre>
<h2>4. XTEA</h2>
<h3>4.1 XTEA 改了什么</h3>
<p>TEA 的 key 下标固定，XTEA 把 key 下标和 <code>sum</code> 绑定：</p>
<pre><code>key[sum &#x26; 3]
key[(sum >> 11) &#x26; 3]
</code></pre>
<p>所以 XTEA 逆向特征比 TEA 更明显。</p>
<h3>4.2 加密流程</h3>
<pre><code>sum = 0
repeat rounds:
    v0 += (((v1 &#x3C;&#x3C; 4) XOR (v1 >> 5)) + v1) XOR (sum + key[sum &#x26; 3])
    sum += delta
    v1 += (((v0 &#x3C;&#x3C; 4) XOR (v0 >> 5)) + v0) XOR (sum + key[(sum >> 11) &#x26; 3])
</code></pre>
<h3>4.3 解密流程</h3>
<pre><code>sum = delta * rounds
repeat rounds:
    v1 -= (((v0 &#x3C;&#x3C; 4) XOR (v0 >> 5)) + v0) XOR (sum + key[(sum >> 11) &#x26; 3])
    sum -= delta
    v0 -= (((v1 &#x3C;&#x3C; 4) XOR (v1 >> 5)) + v1) XOR (sum + key[sum &#x26; 3])
</code></pre>
<h3>4.4 TEA 与 XTEA 的关键对照</h3>
<p>项目TEAXTEAblock64 bit64 bitkey128 bit128 bitkey 下标固定随 <code>sum</code> 变化强特征<code>k0/k1/k2/k3sum&#x26;3</code>、<code>sum>>11&#x26;3</code>轮数口径32 cycles常见 32 rounds</p>
<p>如果只看到 <code>delta</code>、<code>&#x3C;&#x3C;4</code>、<code>>>5</code>，还不能直接判断 TEA，要继续看 key 下标。</p>
<h2>5. XXTEA</h2>
<h3>5.1 XXTEA 和 TEA/XTEA 的关系</h3>
<p>TEA/XTEA 处理：</p>
<pre><code>[v0, v1]
</code></pre>
<p>XXTEA 处理：</p>
<pre><code>[v0, v1, v2, ..., v(n-1)]
</code></pre>
<p>它不是 8 字节一组独立加密，而是整个 word 数组一起扩散。</p>
<h3>5.2 轮数</h3>
<pre><code>rounds = 6 + 52 // n
</code></pre>
<p><code>n</code> 是 32 位 word 数。看到 <code>6 + 52 / n</code> 基本就是 XXTEA。</p>
<h3>5.3 MX 函数</h3>
<p>常见宏：</p>
<pre><code>#define MX (((z >> 5 ^ y &#x3C;&#x3C; 2) + (y >> 3 ^ z &#x3C;&#x3C; 4)) ^ ((sum ^ y) + (key[(p &#x26; 3) ^ e] ^ z)))
</code></pre>
<p>这里的变量名看着短，其实分工很明确：<code>y</code> 是右侧 word，<code>z</code> 是左侧或者上一个已经更新过的 word，<code>p</code> 是当前下标，<code>e</code> 来自 <code>(sum >> 2) &#x26; 3</code>，最后 key 下标用 <code>(p &#x26; 3) ^ e</code> 算出来。把这几个位置对齐，XXTEA 的循环就没那么绕了。</p>
<p>Python 里推荐加满括号：</p>
<pre><code>mx = (((z >> 5) ^ (y &#x3C;&#x3C; 2)) + ((y >> 3) ^ (z &#x3C;&#x3C; 4))) ^ ((s ^ y) + (k[(p &#x26; 3) ^ e] ^ z))
</code></pre>
<h3>5.4 加密流程</h3>
<pre><code>rounds = 6 + 52 // n
sum = 0
z = v[n - 1]

repeat rounds:
    sum += delta
    e = (sum >> 2) &#x26; 3
    for p = 0..n-2:
        y = v[p + 1]
        v[p] += MX
        z = v[p]
    y = v[0]
    v[n - 1] += MX
</code></pre>
<h3>5.5 解密流程</h3>
<pre><code>sum = rounds * delta
y = v[0]

while sum != 0:
    e = (sum >> 2) &#x26; 3
    for p = n-1..1:
        z = v[p - 1]
        v[p] -= MX
        y = v[p]
    z = v[n - 1]
    v[0] -= MX
    sum -= delta
</code></pre>
<h3>5.6 长度 word</h3>
<p>XXTEA 核心只处理 <code>uint32_t[]</code>。实际字节串封装常见两种：</p>
<p>封装表现追加原始长度 word解密后最后 4 字节像明文长度只补零到 4 字节倍数解密后末尾可能有 <code>\x00</code></p>
<p>如果解密结果主体正确、末尾奇怪，优先检查是否用了长度 word。</p>
<h2>6. 魔改排查表</h2>
<p>检查项标准常见魔改delta<code>0x9e3779b90x61c88647</code>、随机常量TEA/XTEA 轮数3216、64、自定义sum 初值0非零固定值字节序题目自定大端/小端混用key16 字节ASCII/hex/base64 混淆padding无标准PKCS#7、零填充、NoPaddingXXTEA 长度常追加长度 word裸 word 数组移位TEA <code>&#x3C;&#x3C;4 >>5</code>改移位数或改括号</p>
<p>做题时可以按这个顺序走：先判断它到底是 TEA、XTEA 还是 XXTEA，再确认 key 是 ASCII 还是 hex 解码，接着看 endian、rounds、delta，最后再处理 padding 或长度 word。不要一上来就怀疑密钥错，很多时候只是大小端或轮数没对上。拿 <code>flag{</code>、文件头或者题目给的样例明密文做验证，效率会高很多。</p>
<p>如果是 crackme 里拿 TEA 家族校验输入，动态调试也很好用。先找最终 <code>memcmp/strcmp</code> 或手写比较的位置，往前看一层，通常能看到程序把你的输入按 8 字节或 4 字节切开处理。这个时候记录输入 buffer、key buffer、加密后的结果，再回 Python 里复现。新手不要一开始就试图给每个临时变量起完美名字，先把输入输出对上。</p>
<h2>7. 代码实现：Python 离线工具脚本</h2>
<p>保存为 <code>tea_family_tool.py</code>。一个脚本同时支持 TEA、XTEA、XXTEA，但每个算法是独立函数，方便线下赛直接改魔改逻辑。</p>
<pre><code>#!/usr/bin/env python3
import argparse
import struct

MASK = 0xffffffff
DELTA = 0x9e3779b9


def pad(data, bs):
    n = bs - len(data) % bs
    return data + bytes([n]) * n


def unpad(data, bs):
    n = data[-1]
    if n &#x3C; 1 or n > bs or data[-n:] != bytes([n]) * n:
        raise ValueError("bad padding")
    return data[:-n]


def tea_block(block, key, endian, rounds, dec=False):
    v0, v1 = struct.unpack(endian + "2I", block)
    k = struct.unpack(endian + "4I", key)
    if not dec:
        s = 0
        for _ in range(rounds):
            s = (s + DELTA) &#x26; MASK
            v0 = (v0 + (((v1 &#x3C;&#x3C; 4) + k[0]) ^ (v1 + s) ^ ((v1 >> 5) + k[1]))) &#x26; MASK
            v1 = (v1 + (((v0 &#x3C;&#x3C; 4) + k[2]) ^ (v0 + s) ^ ((v0 >> 5) + k[3]))) &#x26; MASK
    else:
        s = (DELTA * rounds) &#x26; MASK
        for _ in range(rounds):
            v1 = (v1 - (((v0 &#x3C;&#x3C; 4) + k[2]) ^ (v0 + s) ^ ((v0 >> 5) + k[3]))) &#x26; MASK
            v0 = (v0 - (((v1 &#x3C;&#x3C; 4) + k[0]) ^ (v1 + s) ^ ((v1 >> 5) + k[1]))) &#x26; MASK
            s = (s - DELTA) &#x26; MASK
    return struct.pack(endian + "2I", v0, v1)


def xtea_block(block, key, endian, rounds, dec=False):
    v0, v1 = struct.unpack(endian + "2I", block)
    k = struct.unpack(endian + "4I", key)
    if not dec:
        s = 0
        for _ in range(rounds):
            v0 = (v0 + ((((v1 &#x3C;&#x3C; 4) ^ (v1 >> 5)) + v1) ^ (s + k[s &#x26; 3]))) &#x26; MASK
            s = (s + DELTA) &#x26; MASK
            v1 = (v1 + ((((v0 &#x3C;&#x3C; 4) ^ (v0 >> 5)) + v0) ^ (s + k[(s >> 11) &#x26; 3]))) &#x26; MASK
    else:
        s = (DELTA * rounds) &#x26; MASK
        for _ in range(rounds):
            v1 = (v1 - ((((v0 &#x3C;&#x3C; 4) ^ (v0 >> 5)) + v0) ^ (s + k[(s >> 11) &#x26; 3]))) &#x26; MASK
            s = (s - DELTA) &#x26; MASK
            v0 = (v0 - ((((v1 &#x3C;&#x3C; 4) ^ (v1 >> 5)) + v1) ^ (s + k[s &#x26; 3]))) &#x26; MASK
    return struct.pack(endian + "2I", v0, v1)


def ecb(data, key, algo, dec, endian, rounds, use_pad):
    if len(key) != 16:
        raise ValueError("key must be 16 bytes")
    if not dec and use_pad:
        data = pad(data, 8)
    if len(data) % 8:
        raise ValueError("TEA/XTEA data length must be multiple of 8")
    f = tea_block if algo == "tea" else xtea_block
    out = b"".join(f(data[i:i + 8], key, endian, rounds, dec) for i in range(0, len(data), 8))
    return unpad(out, 8) if dec and use_pad else out


def xx_to_words(data, include_len):
    raw_len = len(data)
    n = (raw_len + 3) // 4
    data = data.ljust(n * 4, b"\0")
    words = list(struct.unpack("&#x3C;%dI" % n, data)) if n else []
    if include_len:
        words.append(raw_len)
    return words


def xx_to_bytes(words, include_len):
    if include_len:
        raw_len = words[-1]
        words = words[:-1]
    else:
        raw_len = len(words) * 4
    data = struct.pack("&#x3C;%dI" % len(words), *[w &#x26; MASK for w in words])
    if include_len:
        if raw_len &#x3C; 0 or raw_len > len(data):
            raise ValueError("bad length word")
        return data[:raw_len]
    return data


def xx_key(key):
    return list(struct.unpack("&#x3C;4I", key.ljust(16, b"\0")[:16]))


def xx_encrypt_words(v, k):
    n = len(v)
    if n &#x3C; 2:
        return v[:]
    v = v[:]
    rounds = 6 + 52 // n
    s = 0
    z = v[-1]
    for _ in range(rounds):
        s = (s + DELTA) &#x26; MASK
        e = (s >> 2) &#x26; 3
        for p in range(n - 1):
            y = v[p + 1]
            mx = (((z >> 5) ^ (y &#x3C;&#x3C; 2)) + ((y >> 3) ^ (z &#x3C;&#x3C; 4))) ^ ((s ^ y) + (k[(p &#x26; 3) ^ e] ^ z))
            v[p] = (v[p] + mx) &#x26; MASK
            z = v[p]
        y = v[0]
        p = n - 1
        mx = (((z >> 5) ^ (y &#x3C;&#x3C; 2)) + ((y >> 3) ^ (z &#x3C;&#x3C; 4))) ^ ((s ^ y) + (k[(p &#x26; 3) ^ e] ^ z))
        v[p] = (v[p] + mx) &#x26; MASK
        z = v[p]
    return v


def xx_decrypt_words(v, k):
    n = len(v)
    if n &#x3C; 2:
        return v[:]
    v = v[:]
    rounds = 6 + 52 // n
    s = (rounds * DELTA) &#x26; MASK
    y = v[0]
    while s:
        e = (s >> 2) &#x26; 3
        for p in range(n - 1, 0, -1):
            z = v[p - 1]
            mx = (((z >> 5) ^ (y &#x3C;&#x3C; 2)) + ((y >> 3) ^ (z &#x3C;&#x3C; 4))) ^ ((s ^ y) + (k[(p &#x26; 3) ^ e] ^ z))
            v[p] = (v[p] - mx) &#x26; MASK
            y = v[p]
        z = v[-1]
        p = 0
        mx = (((z >> 5) ^ (y &#x3C;&#x3C; 2)) + ((y >> 3) ^ (z &#x3C;&#x3C; 4))) ^ ((s ^ y) + (k[(p &#x26; 3) ^ e] ^ z))
        v[0] = (v[0] - mx) &#x26; MASK
        y = v[0]
        s = (s - DELTA) &#x26; MASK
    return v


def xxtea(data, key, dec, use_len):
    k = xx_key(key)
    if dec:
        if len(data) % 4:
            raise ValueError("XXTEA ciphertext length must be multiple of 4")
        return xx_to_bytes(xx_decrypt_words(xx_to_words(data, False), k), use_len)
    v = xx_to_words(data, use_len)
    if len(v) &#x3C; 2:
        v.append(0)
    return xx_to_bytes(xx_encrypt_words(v, k), False)


def main():
    ap = argparse.ArgumentParser(description="TEA/XTEA/XXTEA tool")
    ap.add_argument("data", help="hex data")
    ap.add_argument("-a", "--algo", choices=["tea", "xtea", "xxtea"], required=True)
    ap.add_argument("-k", "--key", required=True, help="hex key by default")
    ap.add_argument("--key-raw", action="store_true")
    ap.add_argument("-d", "--decrypt", action="store_true")
    ap.add_argument("-r", "--rounds", type=int, default=32)
    ap.add_argument("--big", action="store_true")
    ap.add_argument("--no-pad", action="store_true")
    ap.add_argument("--xx-no-len", action="store_true")
    args = ap.parse_args()

    key = args.key.encode() if args.key_raw else bytes.fromhex(args.key)
    data = bytes.fromhex(args.data)
    if args.algo in ("tea", "xtea"):
        out = ecb(data, key, args.algo, args.decrypt, ">" if args.big else "&#x3C;", args.rounds, not args.no_pad)
    else:
        out = xxtea(data, key, args.decrypt, not args.xx_no_len)
    print(out.hex())


if __name__ == "__main__":
    main()

<h2>9. 魔改与做题套路</h2>
<p>快速分类可以这么记：</p>
<pre><code>0x9e3779b9 + 固定 k0/k1/k2/k3       -> TEA
0x9e3779b9 + sum&#x26;3 + sum>>11&#x26;3     -> XTEA
0x9e3779b9 + 6+52/n + MX/z/y/e/p   -> XXTEA
</code></pre>
<p>真正卡人的通常不是公式本身，而是实现细节。Python 忘记 <code>&#x26; 0xffffffff</code>、大小端用错、把 hex 文本当 ASCII、TEA/XTEA 轮数口径没对上、XXTEA 忘记长度 word，这些都很常见。还有一个坑是把 XXTEA 当成 8 字节 ECB 去切，结果当然越解越怪，因为它本来处理的是整个 word 数组。</p>
